# CLISAPP 第一学期MVP详细需求文档
> 最小可行产品 (MVP) 完整功能规格与验收标准

## 📋 文档信息
- **产品版本**: MVP 1.0 (第一学期交付)
- **开发周期**: 4周 (Week 9-13, 2025年9月-12月)
- **目标用户**: Queensland居民 (主要)
- **平台**: iOS 15+ / Android 9+
- **技术栈**: React Native + react-native-maps
- **⚠️ 关键依赖**: 数据源选择决策 (影响实现方式)

---

## 🎯 MVP产品定义与范围

### **MVP核心价值命题**
为Queensland居民提供**准确、直观的本地区域信息查询**，帮助用户快速了解居住地或目标区域的环境状况和基本信息。

### **MVP成功标准**
1. **功能完整性**: 100%覆盖Must Have需求
2. **可用性**: 新用户5分钟内完成核心任务
3. **性能**: 首屏加载≤2秒，交互响应≤300ms
4. **稳定性**: 崩溃率<1%，核心功能可用率>99%

### **MVP范围边界**

#### **✅ 包含功能 (Must Have)**
- Queensland全域地图浏览
- LGA/Suburb双层级行政区域显示
- 区域搜索和GPS定位
- 点击查看区域详细信息
- 空气质量数据展示
- 数据来源标注和分辨率回退

#### **❌ 不包含功能 (Won't Have)**
- 用户账号系统和个人化功能
- 收藏和历史记录
- 社交分享功能
- 多环境指标 (降雨、气温、UV - 留待第二学期)
- 实时数据更新和通知
- 高级分析和趋势预测

# 📋 功能需求详细规格

## **FR-001: 地图浏览与缩放** 🔴 Must Have

### **功能描述**
用户可以通过手势操作浏览Queensland全域地图，支持缩放和平移，从全州视图到具体Suburb级别的详细查看。

### **用户故事**
```
作为 Queensland居民
我想要 在地图上自由浏览不同区域
以便 了解各地区的地理位置和空间关系

作为 潜在迁居者
我想要 比较不同区域的位置
以便 选择适合的居住区域
```

### **详细验收标准**

#### **AC-001.1: 默认地图显示**
- **Given**: 用户首次打开应用
- **When**: 应用加载完成
- **Then**: 
  - 地图默认显示Queensland全图视图
  - 所有LGA边界清晰可见
  - 地图中心位于Queensland地理中心
  - 缩放级别适中，能看清主要城市分布

#### **AC-001.2: 手势交互支持**
- **Given**: 地图已加载完成
- **When**: 用户执行手势操作
- **Then**:
  - **双指缩放**: 支持pinch-to-zoom，缩放范围从全州到街道级别
  - **单指拖拽**: 支持地图平移，边界限制在Queensland范围内
  - **双击缩放**: 双击位置为中心放大一级
  - **操作流畅性**: 手势响应延迟<100ms，动画流畅无卡顿

#### **AC-001.3: 性能要求**
- **Given**: 在中端设备上运行 (iPhone 12/Android equivalent)
- **When**: 用户进行地图交互
- **Then**:
  - 地图渲染帧率≥30FPS
  - 首屏地图加载时间≤2.0秒
  - 缩放操作响应时间≤200ms
  - 内存使用<200MB

#### **AC-001.4: 边界约束**
- **Given**: 用户拖拽地图
- **When**: 尝试超出Queensland边界
- **Then**:
  - 地图自动回弹到边界内
  - 不显示Queensland以外的区域
  - 提供平滑的边界约束体验

### **技术实现要求**
- 使用react-native-maps库
- 支持GDA2020坐标系统
- 实现LOD (Level of Detail) 渲染优化
- 缓存关键地图瓦片

### **测试场景**
1. **基础功能测试**: 各种手势操作正常性
2. **性能测试**: 不同设备上的性能表现
3. **边界测试**: 极限缩放和拖拽的边界处理
4. **兼容性测试**: iOS/Android平台一致性

## **FR-002: 行政层级切换** 🔴 Must Have

### **功能描述**
提供LGA (Local Government Area) 和Suburb/Locality两个层级的行政区域边界显示，用户可以根据需要在两个层级间切换。

### **用户故事**
```
作为 区域研究者
我想要 在LGA和Suburb层级间切换
以便 获得不同精度的行政区域信息

作为 房地产买家
我想要 先看LGA整体情况，再查看具体Suburb
以便 做出更好的区域选择决策
```

### **详细验收标准**

#### **AC-002.1: 层级切换控件**
- **Given**: 用户在地图界面
- **When**: 查看右上角控制区域
- **Then**:
  - 显示清晰的"LGA"/"Suburb"切换按钮
  - 当前选中层级有明显的视觉指示
  - 按钮设计符合平台UI规范
  - 触摸区域≥44×44pt (iOS) / 48×48dp (Android)

#### **AC-002.2: 层级切换功能**
- **Given**: 用户在任一层级视图
- **When**: 点击层级切换按钮
- **Then**:
  - 切换动画时间≤1秒
  - 保持当前地图视口中心位置
  - 边界样式相应更新 (LGA边界更粗，Suburb边界更细)
  - 图例和状态指示器同步更新

#### **AC-002.3: LGA层级显示**
- **Given**: 选择LGA层级
- **When**: 地图渲染完成
- **Then**:
  - 显示Queensland所有LGA边界
  - 边界线粗细为2px，颜色为深蓝色(#1976D2)
  - LGA名称在适当缩放级别显示
  - 边界内部半透明填充 (透明度20%)

#### **AC-002.4: Suburb层级显示**
- **Given**: 选择Suburb层级且缩放级别>10
- **When**: 地图渲染完成
- **Then**:
  - 显示当前视图内的Suburb边界
  - 边界线粗细为1px，颜色为中蓝色(#42A5F5)
  - Suburb名称在适当缩放级别显示
  - 实现动态加载以保证性能

#### **AC-002.5: 性能优化**
- **Given**: 用户频繁切换层级
- **When**: 执行切换操作
- **Then**:
  - 切换响应时间≤300ms
  - 内存使用增长<10%
  - 数据预加载减少重复请求
  - 渲染性能保持30FPS+

### **技术实现要求**
- 使用Polygon组件渲染边界
- 实现边界数据的分级加载
- 建立边界样式的配置化管理
- 优化大数据集的渲染性能

### **数据要求**
- Queensland完整LGA边界数据 (GeoJSON格式)
- Suburb/Locality边界数据 (GeoJSON格式)
- 建立LGA-Suburb层级关系映射
- 数据精度：适合1:50000比例尺显示

## **FR-003: 区域搜索** 🔴 Must Have

### **功能描述**
提供地名和邮编搜索功能，支持自动联想提示，用户选择后地图自动飞行到目标区域并高亮显示。

### **用户故事**
```
作为 初次访问Queensland的用户
我想要 搜索具体地名 (如"Sunnybank", "Ipswich")
以便 快速定位到我关心的区域

作为 了解邮编的用户
我想要 通过邮编搜索 (如"4000", "4102")
以便 精确找到对应的区域
```

### **详细验收标准**

#### **AC-003.1: 搜索界面**
- **Given**: 用户在地图主界面
- **When**: 查看顶部区域
- **Then**:
  - 显示搜索框，占位符文字"搜索地名或邮编..."
  - 搜索框宽度占屏幕宽度80%
  - 包含搜索图标和清除按钮
  - 支持键盘输入和语音输入 (如设备支持)

#### **AC-003.2: 自动联想功能**
- **Given**: 用户在搜索框输入文字
- **When**: 输入字符≥3个
- **Then**:
  - 显示最多10个相关建议
  - 建议列表包含地名、邮编、LGA名称
  - 匹配算法支持模糊搜索和前缀匹配
  - 建议出现时间≤500ms

#### **AC-003.3: 搜索结果处理**
- **Given**: 用户选择搜索建议
- **When**: 点击建议项目
- **Then**:
  - 地图平滑飞行到目标区域
  - 飞行动画时间1-2秒，速度适中
  - 目标区域边界高亮显示 (橙色边框，3px宽度)
  - 自动调整缩放级别以适合区域大小

#### **AC-003.4: 搜索数据覆盖**
- **Given**: 搜索功能可用
- **When**: 用户搜索Queensland内容
- **Then**:
  - 覆盖所有Queensland LGA名称
  - 覆盖主要Suburb/Locality名称 (人口>1000)
  - 覆盖所有Queensland邮编 (4000-4999)
  - 包含常用别名和简称

#### **AC-003.5: 错误处理**
- **Given**: 用户输入无效搜索内容
- **When**: 搜索无结果
- **Then**:
  - 显示"未找到相关结果"提示
  - 提供搜索建议 (如检查拼写、尝试其他关键词)
  - 不清除用户输入，允许修改
  - 记录搜索失败日志用于优化

### **技术实现要求**
- 建立本地搜索索引 (使用Fuse.js或类似库)
- 实现地理编码和反向地理编码
- 支持搜索结果的权重排序
- 缓存常用搜索结果

### **搜索数据结构**
```javascript
{
  id: "unique_id",
  name: "Brisbane City",
  type: "LGA" | "Suburb" | "Postcode",
  postcode: "4000",
  coordinates: [153.0251, -27.4698],
  bounds: [[west, south], [east, north]],
  searchTerms: ["Brisbane", "CBD", "4000"]
}
```

## **FR-004: 选区信息卡** 🔴 Must Have

### **功能描述**
用户点击地图上的区域后，弹出信息卡显示该区域的详细信息，包括名称、行政层级、空气质量数据、数据来源和采集时间等。

### **用户故事**
```
作为 关心环境质量的居民
我想要 点击地图上的区域查看空气质量信息
以便 了解该区域的环境健康状况

作为 数据准确性关注者
我想要 看到数据的来源和采集时间
以便 判断信息的可信度和时效性
```

### **详细验收标准**

#### **AC-004.1: 区域选择交互**
- **Given**: 地图显示LGA或Suburb边界
- **When**: 用户点击边界内区域
- **Then**:
  - 选中区域边界高亮显示 (橙色，3px宽度)
  - 其他区域边界淡化显示 (透明度50%)
  - 点击响应时间≤200ms
  - 支持点击切换选择不同区域

#### **AC-004.2: 信息卡显示**
- **Given**: 用户选中区域
- **When**: 点击操作完成
- **Then**:
  - 信息卡从底部滑入动画 (300ms)
  - 显示在屏幕底部，占屏幕高度30-40%
  - 包含关闭按钮 (×) 在右上角
  - 支持上滑展开查看更多信息

#### **AC-004.3: 基本信息显示**
- **Given**: 信息卡已打开
- **When**: 显示区域基本信息
- **Then**:
  - **区域名称**: 大号字体显示 (20sp)
  - **行政层级**: 显示"LGA"或"Suburb"标签
  - **邮编**: 如果可用，显示对应邮编
  - **人口数据**: 显示2021年人口数据 (如果可用)

#### **AC-004.4: 空气质量信息**
- **Given**: 区域有空气质量数据
- **When**: 显示环境指标
- **Then**:
  - **PM2.5数值**: 大号数字显示，包含单位 (μg/m³)
  - **健康状态**: 显示WHO标准的健康评级
  - **颜色编码**: 使用标准的空气质量颜色
  - **健康建议**: 提供简短的健康影响说明

#### **AC-004.5: 数据来源标注**
- **Given**: 显示任何数据
- **When**: 用户查看信息卡
- **Then**:
  - 每项数据显示来源 (如"ABS 2021", "BOM 2024")
  - 数据采集时间或更新时间
  - 数据分辨率说明 (LGA级/Suburb级)
  - 数据质量指示器 (如果适用)

#### **AC-004.6: 分辨率回退处理**
- **Given**: Suburb级数据缺失
- **When**: 显示该Suburb信息
- **Then**:
  - 自动显示对应LGA的数据
  - 明确标注"使用LGA数据 (Suburb数据暂无)"
  - 使用不同的视觉样式区分 (斜体或淡色)
  - 提供数据缺失的友好解释

#### **AC-004.7: 无数据处理**
- **Given**: 区域完全无数据
- **When**: 用户选择该区域
- **Then**:
  - 显示"数据暂无"状态
  - 提供简短说明和建议
  - 显示区域基本信息 (名称、层级)
  - 提供反馈入口收集用户需求

### **信息卡布局设计**
```
┌─────────────────────────────────────┐
│ 区域名称 (Brisbane City)        × │
│ LGA • 邮编: 4000                   │
├─────────────────────────────────────┤

│ 15 μg/m³ [良好]                     │
│ 💚 适合户外活动                     │
├─────────────────────────────────────┤
│ 人口: 25,463 (ABS 2021)            │
│ 数据更新: 2024年9月                 │
│ 分辨率: LGA级                       │
└─────────────────────────────────────┘
```

## **FR-005: GPS定位功能** 🟡 Should Have

### **功能描述**
提供"定位到我"功能，获取用户当前位置并在地图上居中显示，自动匹配到对应的Suburb或LGA区域。

### **用户故事**
```
作为 想了解本地信息的用户
我想要 快速定位到我当前的位置
以便 查看我所在区域的信息

作为 移动中的用户
我想要 快速回到我的当前位置
以便 了解周围环境状况
```

### **详细验收标准**

#### **AC-005.1: 定位按钮界面**
- **Given**: 用户在地图界面
- **When**: 查看地图控件
- **Then**:
  - 定位按钮位于右下角
  - 使用标准定位图标 (🎯)
  - 按钮大小48×48dp，易于点击
  - 有清晰的背景和边框

#### **AC-005.2: 权限请求处理**
- **Given**: 用户首次点击定位按钮
- **When**: 应用需要位置权限
- **Then**:
  - 显示权限请求对话框
  - 包含清晰的权限说明文字
  - 说明位置数据仅用于地图定位
  - 用户拒绝权限后应用不崩溃

#### **AC-005.3: 定位成功处理**
- **Given**: 用户授权位置权限
- **When**: GPS定位成功
- **Then**:
  - 地图平滑移动到用户位置
  - 显示用户位置标记 (蓝色圆点)
  - 自动匹配到对应Suburb/LGA
  - 可选择显示该区域信息卡

#### **AC-005.4: 定位失败处理**
- **Given**: GPS定位失败
- **When**: 超时或信号不好
- **Then**:
  - 显示友好的错误提示
  - 建议用户检查位置服务设置
  - 提供手动搜索的替代方案
  - 记录错误日志但不影响其他功能

#### **AC-005.5: 性能要求**
- **Given**: 用户点击定位按钮
- **When**: 定位过程进行中
- **Then**:
  - 显示加载指示器
  - 定位时间≤10秒 (正常网络环境)
  - 定位精度≤100米 (城市环境)
  - 支持后台定位服务

### **技术实现要求**
- 使用react-native-geolocation-service
- 支持iOS和Android的位置权限管理
- 实现位置缓存避免频繁请求
- 处理权限拒绝和设备不支持场景

## **FR-006: 数据分辨率回退** 🔴 Must Have

### **功能描述**
当Suburb级别的数据缺失时，自动显示对应LGA级别的数据，并在UI中明确标注数据来源层级，确保用户始终能获得可用信息。

### **用户故事**
```
作为 查看数据的用户
我想要 在Suburb数据缺失时自动看到LGA数据
以便 仍能获得有用的区域信息

作为 关心数据准确性的用户
我想要 清楚知道显示的是哪个层级的数据
以便 正确理解数据的代表性
```

### **详细验收标准**

#### **AC-006.1: 数据可用性检测**
- **Given**: 用户查看任意区域信息
- **When**: 系统检查数据可用性
- **Then**:
  - 检测覆盖100%的数据字段
  - 检测过程时间≤100ms
  - 建立Suburb到LGA的映射关系
  - 记录数据缺失统计用于改进

#### **AC-006.2: 回退逻辑实现**
- **Given**: Suburb级数据缺失
- **When**: 显示该Suburb信息
- **Then**:
  - 自动使用对应LGA的数据
  - 保持数据结构一致性
  - 标记数据来源层级
  - 不影响界面显示性能

#### **AC-006.3: UI标注显示**
- **Given**: 使用LGA回退数据
- **When**: 在信息卡中显示
- **Then**:
  - 明确标注"使用LGA数据"
  - 使用不同颜色或斜体样式区分
  - 提供简短的解释说明
  - 包含原始LGA名称

#### **AC-006.4: 完全无数据处理**
- **Given**: LGA和Suburb都无数据
- **When**: 用户选择该区域
- **Then**:
  - 显示"数据暂无"状态
  - 提供友好的解释和建议
  - 显示区域基本信息 (名称等)
  - 建议用户查看邻近区域

#### **AC-006.5: 数据质量指示**
- **Given**: 任何数据显示
- **When**: 用户查看信息卡
- **Then**:
  - 显示数据完整性指示器
  - 标注数据的时效性
  - 提供数据来源链接 (如适用)
  - 支持用户反馈数据问题

### **回退逻辑示例**
```
Suburb "Sunnybank" → 数据缺失
↓
查找对应LGA "Brisbane City"
↓
显示: "Brisbane City (LGA级数据)"
标注: "Sunnybank数据暂无，显示LGA数据"
```

# 📊 非功能需求

## **NFR-001: 性能要求**

### **响应时间要求**
- **首屏加载**: ≤2.0秒 (中端设备，良好网络)
- **地图交互**: 手势响应≤100ms，渲染≤200ms
- **搜索响应**: 自动联想≤500ms，结果跳转≤1秒
- **信息卡**: 显示≤300ms，数据加载≤1秒
- **层级切换**: ≤1秒完成，保持视口中心

### **性能基准设备**
- **iOS**: iPhone 12 (A14 Bionic)
- **Android**: Samsung Galaxy S21 (Snapdragon 888)
- **内存**: 峰值使用≤200MB
- **电池**: 正常使用1小时消耗≤5%

## **NFR-002: 兼容性要求**

### **平台支持**
- **iOS**: 15.0+ (支持iPhone 7及以上)
- **Android**: API Level 28+ (Android 9.0+)
- **屏幕尺寸**: 4.7"-7" (手机), 8"-13" (平板)
- **分辨率**: 适配各种DPI (ldpi到xxxhdpi)

### **网络环境**
- **在线模式**: 需要网络连接获取数据
- **弱网优化**: 2G网络环境下基本可用
- **离线缓存**: 缓存最近访问的区域数据
- **数据压缩**: 地理数据压缩传输

## **NFR-003: 可用性要求**

### **用户体验**
- **学习成本**: 新用户5分钟内掌握基本操作
- **任务完成**: 查找区域信息2分钟内完成
- **错误恢复**: 所有错误状态提供明确指导
- **可达性**: 支持大字体、高对比度模式

### **界面设计**
- **触控区域**: 最小44×44pt (iOS) / 48×48dp (Android)
- **颜色对比**: 满足WCAG AA级别要求
- **文字大小**: 最小12pt，重要信息≥14pt
- **语言**: 全英文界面，术语一致性

## **NFR-004: 可靠性要求**

### **稳定性指标**
- **崩溃率**: <1%/月活用户
- **功能可用率**: 核心功能>99%时间可用
- **数据准确性**: 显示数据与源数据100%一致
- **错误处理**: 所有异常情况优雅处理

### **容错能力**
- **网络异常**: 显示缓存数据或友好提示
- **数据缺失**: 自动回退或明确说明
- **权限拒绝**: 功能降级但不影响其他功能
- **设备兼容**: 低端设备自动降级渲染质量
